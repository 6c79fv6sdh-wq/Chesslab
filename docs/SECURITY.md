# Безопасность и границы доверия

## Что защищено кодом

- административные команды проходят allowlist `ADMIN_IDS`;
- владелец заказа проверяется в application service, а не только в Telegram-router;
- оплату Stars нельзя подтвердить с другим payload, charge ID, количеством или валютой;
- invoice payload, charge ID и ключ идемпотентности уникальны;
- лимит размера применяется повторно до парсинга и записи через любой presentation adapter;
- имена файлов очищаются, путь после `resolve()` обязан оставаться внутри `STORAGE_ROOT`;
- PGN разбирается как шахматный формат, PDF проверяется по сигнатуре, запись атомарна и снабжена
  SHA-256;
- worker повторно сверяет SHA-256 исходного PGN перед анализом;
- Lichess adapter обращается только к сконфигурированному base URL, кодирует username, ограничивает
  ответ по числу партий, байтам и общему timeout;
- путь Stockfish задается конфигурацией и обязан указывать на существующий файл; пользовательские
  данные не подставляются в shell-команду;
- fast/deep node limits, лимиты корпуса и числа кандидатов ограничивают вычислительную нагрузку;
- автокомплект повторно проходит application-валидацию JSON/PDF/PGN до статуса `review_pending`;
- администратор не может комплектовать или выдавать дело, закрепленное за другим администратором;
- HTML-поля, введенные пользователем, экранируются перед показом в Telegram.

## Что обязан обеспечить владелец

- не передавать токен в чат, Git, логи и архивы; при утечке немедленно перевыпустить его в
  BotFather;
- использовать отдельного Unix-пользователя/контейнер и закрытые права на БД и `STORAGE_ROOT`;
- резервировать БД и файлы вместе, иначе ссылки на артефакты потеряют смысл;
- установить настоящий `SUPPORT_CONTACT`, проверить регламент, возвраты и применимые юридические
  требования до запуска продаж;
- не включать `manual` payment и `AUTO_CREATE_SCHEMA` в production;
- использовать Redis для FSM и Telegram Stars для цифровой услуги внутри Telegram.
- устанавливать Stockfish и системные пакеты из доверенного репозитория, фиксировать версию образа;
- определить срок хранения PGN, отчетов, контактов и платежного аудита, а также процедуру удаления;
- не направлять `LICHESS_BASE_URL` на внутренние сервисы или произвольные пользовательские URL.

## Остаточные риски MVP

PGN, JSON и PDF хранятся локально без прикладного шифрования; защита зависит от диска/хоста.
Stockfish запускается локальным процессом без отдельного sandbox-профиля, поэтому контейнер и
непривилегированный пользователь остаются частью границы безопасности. SQLite и очередь рассчитаны
на один процесс. До команды сотрудников, облачного хранилища или горизонтального масштабирования
нужны PostgreSQL, объектное хранилище с серверным шифрованием, политика удаления, метрики и
централизованный мониторинг.
