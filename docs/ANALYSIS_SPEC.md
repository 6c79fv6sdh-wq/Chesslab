# Спецификация автоматического анализа v0.2

## Контракт

Вход: один PGN-корпус до 50 партий и точное имя исследуемого игрока. Для Lichess тот же PGN
получается публичным API. Выход всегда имеет стабильную схему:

1. `analysis.json` - машинный манифест, методика, знаменатели, решения и конверсия;
2. `report.pdf` - доказательное заключение и план на 14 дней;
3. `errors_WHITE.pgn` и `errors_BLACK.pgn`;
4. `conversion_WHITE.pgn` и `conversion_BLACK.pgn`.

Автоматическая генерация не равна автоматической выдаче. Полный и повторно провалидированный
комплект переводит дело в `review_pending`. Только администратор может просмотреть его, закрепить
дело за собой, перевести в `ready` и выполнить `/done`.

## Единица анализа

Оценка всегда приводится к точке зрения исследуемого игрока. Положительное число хорошо для него
независимо от цвета. Решением считается только ход этого игрока; знаменатель никогда не включает
ходы соперника.

Для каждого решения выполняются два поиска:

- лучший ход из исходной позиции;
- сыгранный ход как единственный разрешенный корневой ход.

Потеря равна `max(0, best - played)`. Матовые оценки переводятся во внутреннюю шкалу только для
сортировки; в отчете мат остается матом, а не карнавальной пешкой `+999.99`.

## Два прохода

Fast pass рассматривает все решения. Каждый независимый поиск начинается с `Clear Hash`, поэтому
сравнение лучшего и сыгранного ходов не зависит от того, кому достался прогретый кэш. В deep pass
попадают не более 64 сильнейших кандидатов:
потеря не меньше 1.20 пешки, изменение матового статуса, пат или срыв выигрышной позиции. Перед
каждой deep-оценкой hash также очищается. Узлы, версия движка и параметры записываются в манифест.

`MultiPV=1`: официальный Stockfish предупреждает, что дополнительные линии отнимают ресурс у
лучшего хода. Для доказательства ошибки важнее один максимально надежный эталон, а не веер
риторических павлиньих хвостов.

## Классификация

Каждая подтвержденная позиция получает ровно один главный тег по приоритету:

1. `stalemate` - выигранная позиция немедленно стала патом;
2. `mate` - пропущен свой форсированный мат или разрешен мат сопернику;
3. `queen_piece` - лучший ответ немедленно забирает ферзя/фигуру;
4. `conversion` - перевес не меньше +2 упал ниже +0.5;
5. `check_tempo` - форсирующий ответ начинается шахом;
6. `other` - подтвержденный крупный провал без честно доказанного мотива выше.

Последний тег нужен, чтобы система не выдумывала «психологию» из одной цифры. Ложная конкретность
хуже честной общей категории: это уже не диагностика, а философский понос в хрустальном графине.

## Конверсия

Считаются пороги +2, +3 и +5. Порог считается устойчиво достигнутым после двух последовательных
позиций игрока не ниже него. Для каждого порога отчет показывает:

- число партий, достигших порога;
- сколько позднее упали ниже +0.5;
- сколько позднее перешли в минус;
- сколько не закончились победой.

В тренировочный пак попадает первая устойчивая позиция из партии, если перевес затем сорван или
партия не выиграна. Лучший ход намеренно не записывается.

Корпусные проценты считаются по fast pass, иначе стоимость росла бы пропорционально всем позициям.
Каждая выбранная для учебного пака стартовая позиция отдельно подтверждается deep pass; в JSON
хранятся обе оценки. Поэтому агрегат и доказательный пример не выдаются за одну и ту же точность.

## PGN-инварианты

- один chapter = одна стартовая FEN-позиция;
- `SetUp=1`, `FEN`, `Variant=From Position`, `Orientation=white|black`;
- ориентация всегда со стороны игрока;
- WHITE и BLACK никогда не смешиваются;
- одинаковые позиции дедуплицируются по первым четырем полям FEN;
- лучший ход скрыт, но источник, ход срыва, две оценки и задача сохранены в комментарии;
- общий лимит подтвержденных ошибок - 64.

## Границы утверждений

PGN позволяет измерять шахматные решения, но не читать мысли и не доказывать читерство. PDF
разделяет наблюдаемые факты, тренерские гипотезы и ограничения. Любые персональные объяснения до
движка сначала формулирует ученик или тренер; автоматика проверяет позиции, а не изображает
электронного Фрейда из районного МФЦ.
