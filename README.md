# Science Chess Speed Lab

_by Vladislav Dmitrovsky_

Локальный тренажёр моторики и скорости для ultrabullet. Работает целиком в браузере,
без сервера, аккаунтов и внешних запросов. Все данные лежат в IndexedDB на устройстве.

С Lichess во время игры тренажёр не взаимодействует и вводить ходы за вас не умеет.

## Адрес сайта

Тренажёр опубликован на GitHub Pages и открывается у кого угодно без входа:

```
https://6c79fv6sdh-wq.github.io/Speed-lab/
```

Сайт обновляется сам. Workflow `.github/workflows/pages.yml` на каждый push
в `main` прогоняет тесты, собирает проект и перезаписывает ветку `gh-pages`,
которую раздаёт Pages. Если тесты падают, публикации не будет.

Запустить публикацию вручную: вкладка **Actions** →
**Сборка сайта в ветку gh-pages** → **Run workflow**.

Настройка Pages уже сделана: источник — ветка `gh-pages`, папка `/(root)`.

## Движок

В «Скрэмбле» соперника считает Stockfish 18 Lite, однопоточная WASM-сборка.
Однопоточная выбрана намеренно: многопоточной нужен SharedArrayBuffer,
а для него — заголовки COOP/COEP, которых на GitHub Pages не выставить.

Файлы лежат в `public/engine` и в предзагрузку service worker не попадают:
иначе первое открытие сайта весило бы 7 МБ. Движок подтягивается при первом
использовании и после этого работает офлайн.

Сила задаётся через `UCI_Elo` (диапазон сборки 1320–3190), то есть «Эло 2200»
означает именно это значение, а не название профиля. Отдельно выбирается темп
хода — он влияет только на задержку перед ответом.

Рядом остаётся простой бот на один полуход: он не требует загрузки и полезен,
когда нужен заведомо слабый и мгновенный соперник.

Проверка того, что шкала силы работает:

```bash
npm i --no-save stockfish
MT=50 G=12 node tools/engine-match.mjs
```

Замеренный результат: Эло 2200 против Эло 1400 — 88% очков (10,5 из 12),
Эло 2200 против Эло 3000 — 0% (0 из 12). Шкала монотонна и реально влияет
на игру. Абсолютная привязка `UCI_Elo` к рейтингу Lichess — заявление
разработчиков Stockfish, независимо я её не проверял.

Stockfish распространяется по GPLv3, текст лицензии — `public/engine/LICENSE-stockfish.txt`.

## Запуск в Codespaces

Всё запускается одной строкой в терминале, десктоп не нужен.

```bash
npm install
```

Разработка с горячей перезагрузкой:

```bash
npm run dev
```

Тесты:

```bash
npm test
```

Продакшн-сборка (в неё входит service worker, без него не будет offline):

```bash
npm run build
```

Просмотр собранной версии:

```bash
npm run preview
```

## Как открыть на iPad

Просто открой в Safari опубликованный адрес:

```
https://6c79fv6sdh-wq.github.io/Speed-lab/
```

Для работы совсем без сети страницу надо один раз открыть при интернете:
service worker скачает всё в кеш, после этого приложение работает offline.

Если нужна не опубликованная, а локальная сборка из Codespaces: запусти
`npm run preview` (именно сборку, в режиме `npm run dev` service worker выключен),
затем в панели **Ports** поставь порту `4173` видимость **Public** и открой адрес.

## Где лежат данные упражнений

| Что | Файл |
| --- | --- |
| Линии дебютных репертуаров, SAN | `src/data/repertoire.ts` |
| Позиции для модуля Premove, FEN | `src/data/premove-positions.ts` |
| Задачи «висящая фигура» | `src/data/puzzles-hanging.ts` |
| Исходный PGN этих задач | `data/lichess-hanging-piece-200-white.pgn` |

Задачи импортируются из PGN скриптом:

```bash
node tools/import-puzzles.mjs data/lichess-hanging-piece-200-white.pgn > src/data/puzzles-hanging.ts
```

Скрипт проверяет каждую задачу движком правил и отбрасывает битые. Чтобы
добавить свои задачи, положи PGN рядом и прогони скрипт на нём.

Оба файла проверяются автотестами: `tests/repertoire.test.ts` проигрывает каждую
линию движком от начальной позиции, `tests/premove-positions.test.ts` проверяет
валидность каждого FEN и легальность ожидаемого, ответного и неожиданного ходов.
Если добавишь линию или позицию с ошибкой, `npm test` это поймает.

Загрузка своего PGN в первой версии не предусмотрена.

## Вкладки

1. **Калибровка** — размер доски, способ ввода, координаты, профиль устройства,
   метка настроек указателя. Эти значения пишутся в каждый замер всех модулей.
2. **Моторика** — 30 повторов source-target с телеметрией указателя.
3. **Premove** — форсированное взятие, safe/unsafe, отмена.
4. **Реакция** — бесплатное взятие (200 реальных задач Lichess), безопасный шах,
   дельта позиции; экспозиция без лимита / 500 / 300 / 200 мс.
5. **Дебюты** — три репертуара, задержка ответа на каждом узле, заминки.
6. **Скрэмбл** — партии 15/10/5 секунд против Stockfish с выбором силы
   либо против простого бота.
7. **Данные** — сводные таблицы, экспорт и импорт JSON, очистка измерений.

## Хранение, экспорт и импорт

Всё лежит в IndexedDB `sciencechess-hyperlab`: настройки калибровки, сессии,
замеры и статистика дебютных узлов.

На вкладке **Данные**:

- **Экспорт в поле** — JSON в текстовое поле,
- **Скачать файл** — тот же JSON файлом,
- **Импорт из поля** и **Импорт из файла** — обратная загрузка (слияние по id),
- **Очистить измерения** — удаляет сессии, замеры и статистику узлов,
  настройки калибровки при этом остаются.

Синхронизации между устройствами нет и не планируется: перенос только через экспорт.
