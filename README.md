# Чест-досье

Telegram concierge для доказательной шахматной диагностики. Это восстановленная и продолженная
версия проекта из сломанной Work-ветки: старые девять файлов сохранены как совместимые входные
точки, а реальная реализация вынесена в модульный пакет `src/chess_dossier`.

## Что уже работает

- `/start`, холодная архивно-канцелярская подача и конфигурируемый словарь;
- анкета: Lichess / PGN / Chess.com через PGN, рейтинг, контроль, язык, контакт;
- лимит не более трех новых дел в московские сутки;
- ручное подтверждение платежа в development и Telegram Stars в production;
- прием и проверка PGN: кодировка, синтаксис, число партий, лимит 50;
- прием ника или ссылки Lichess и ограниченный экспорт партий через официальный API;
- двухпроходный анализ Stockfish: быстрый проход всех решений и независимая deep-проверка
  критических позиций после очистки hash;
- единая оценка со стороны исследуемого игрока, дедупликация партий/позиций и явные знаменатели;
- машинный `analysis.json`, доказательный PDF и четыре тренировочных PGN с правильной ориентацией;
- SQLite, миграции Alembic, журнал всех переходов и идемпотентность;
- фоновый worker, аварийное состояние, повторный запуск и обязательная ручная проверка результата;
- админский реестр, предпросмотр, подтверждение оплаты, принятие дела в работу;
- загрузка/замена обязательного комплекта и доставка клиенту: JSON + PDF + четыре PGN
  (в полностью ручном режиме JSON необязателен);
- возобновляемая выдача: после сетевого сбоя уже врученные файлы повторно не отправляются;
- безопасное локальное файловое хранилище с SHA-256 и атомарной записью;
- Redis для FSM в production; MemoryStorage допускается только локально;
- автоматические тесты домена, БД, Lichess-границы, анализа и полного concierge-процесса.

Автоматика не выдает результат напрямую. После генерации дело переходит в `review_pending`;
администратор просматривает комплект и только затем разрешает доставку. Это сознательная граница:
движок проверяет позиции, а не изображает всеведущего электронного тренера.

## Быстрый запуск

```bash
cp .env.example .env
uv sync --extra dev
uv run alembic upgrade head
uv run chess-dossier
```

В `.env` нужны `TELEGRAM_BOT_TOKEN`, `ADMIN_IDS` и `SUPPORT_CONTACT`. Секреты нельзя коммитить.
Для автоматического анализа также нужны `ANALYSIS_ENABLED=true` и существующий исполняемый файл в
`STOCKFISH_PATH`. Docker Compose устанавливает Stockfish и шрифт PDF сам.

Локальный `PAYMENT_MODE=manual` предназначен для разработки и concierge-проверки. Для production
используется `PAYMENT_MODE=telegram_stars` и положительный `STAR_PRICE`. Telegram требует Stars для
цифровых товаров и услуг внутри ботов; сторонний эквайринг в этот поток сознательно не зашит.

## Производственный цикл

1. Клиент заполняет карточку и получает номер `CD-YYYYMMDD-XXXXXX`.
2. После оплаты администратор вводит `/paid НОМЕР` (или приходит успешный Stars payment).
3. Клиент присылает Lichess-профиль либо PGN.
4. Worker получает PGN, запускает Stockfish и создает `analysis.json`, PDF и четыре PGN.
5. Дело получает статус `review_pending`; администратор выполняет `/preview НОМЕР`.
6. После проверки `/deliver НОМЕР` закрепляет дело за администратором. Существующие файлы можно
   оставить или заменить вручную:
   - `analysis.json`
   - `report.pdf`
   - `errors_WHITE.pgn`
   - `errors_BLACK.pgn`
   - `conversion_WHITE.pgn`
   - `conversion_BLACK.pgn`
   План на 14 дней входит в `report.pdf`; при необходимости его можно приложить отдельным
   `plan_14d.pdf`.
7. `/done` проверяет комплект, отправляет файлы клиенту и только после успешной отправки фиксирует
   `delivered`.

Если анализ остановился, статус становится `failed`, причина видна администратору, а `/retry НОМЕР`
возвращает дело в очередь. При штатной остановке процесса незавершенное автоматическое дело также
можно безопасно вернуть в очередь этой командой.

## Локальный анализ без Telegram

```bash
uv run chess-dossier-analyze \
  --pgn examples/demo_games.pgn \
  --player DemoPlayer \
  --output ./demo-output \
  --stockfish /usr/games/stockfish
```

Имя игрока должно точно совпадать с `White` или `Black` в PGN без учета регистра. Команда создает
тот же комплект из шести файлов, который использует worker.
